# tools — 從螢幕錄影抽出投影片

> **⚠️ 使用前請自行確認你有權使用手上的錄影檔。**
> 本專案不提供任何課程素材，這裡只有工具。

## extract_slides.py

從 Zoom（或任何螢幕分享）錄影中偵測換頁，把每一張投影片存成 PNG，
並產生帶時間碼的索引 JSON。

```bash
pip install opencv-python numpy
py -3 tools/extract_slides.py <影片檔> <輸出資料夾> <標籤>
```

輸出的檔名格式：

```
L13_s030_035m26s.png
 │    │      └── 影片中的 35 分 26 秒
 │    └───────── 第 30 張
 └────────────── 標籤（第 13 節）
```

**可以直接對回原始影片的時間碼**，方便查證。

### 要調的參數

```python
CROP = dict(x0=150, y0=130, x1=925, y1=700)   # ★ 投影片在畫面上的位置
SAMPLE_SEC  = 1.5    # 每隔幾秒取樣一次
DIFF_TH     = 6.0    # 換頁判定門檻（平均絕對差）
STABLE_TH   = 2.0    # 畫面穩定判定
DEDUP_TH    = 3.5    # 與上一張已存圖的差異低於此值就不存
MIN_GAP_SEC = 3.0    # 兩張之間至少間隔幾秒
```

**`CROP` 一定要先自己量。** 每個人的 Zoom 版面不同。
先隨便截一張圖，量出投影片區域的四個座標再填進去。
**框太大會把聊天室、工具列、滑鼠游標算進去，導致誤判換頁。**

## ★ 三條經驗教訓

用這個工具讀出來的內容，如果要拿來校訂筆記，請記住這三件事 ——
這是實際做過一輪之後付出代價換來的：

**① 先放大，再下判斷**
縮圖的解析度會騙你。`7.787I`（後面那個是變數 `I`）在縮圖上看起來像 `7.7871`；
`−0.021009` 的負號也可能整個糊掉。
**要主張「教材印錯了」之前，一定先把原圖裁切放大再看一次。**

**② 數字錯誤要用「邊界條件」驗算，不要憑印象**
```
DIN 6164 的 Darkness 常數  →  用「最佳色的 D 必須 = 0」驗 → 得 6.1723
CIELUV 的線性段係數        →  用「κ·ε = 8」驗            → 得 903.2963
Munsell 明度多項式          →  用「V = 10 → Y ≈ 100」驗
```
**算得出來的才寫進勘誤表**，算不出來的就標「存疑」，不要猜。

**③ 同一份教材可能一張印錯、另一張印對**
Munsell 的五次多項式在某一節印成 `+0.021009V⁴`（錯），
在另一節印成 `−0.021009V⁴`（對）。
**找到「對的那一張」，比自己推導更有說服力。**

## 逐字稿

本專案不含逐字稿。若你有錄影，可以自己跑
[Whisper](https://github.com/openai/whisper) 產生：

```bash
whisper <影片檔> --language en --model large-v3 --output_format srt
```

**⚠️ 注意**：講者若帶口音，**專有名詞的誤植會非常嚴重**
（`Hunt→Hound`、`MacAdam→McArden`、`Ostwald→Osterwee`、`CIEDE2000→CIEP 2000`…）。
`references/00-glossary.md` 底部有一份完整的勘誤對照表，
**引用逐字稿之前先查那張表。**

**最容易踩的陷阱**：`CIELAB` 與 `CIELUV` 都會被轉成 `"C-Lab"`，只能靠上下文分辨。
